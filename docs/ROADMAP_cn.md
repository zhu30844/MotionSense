# 路线图

[English](ROADMAP.md) | 简体中文

最后编辑：2026-11-27

## 2.0 里程碑

2.0 不提供从 1.x 迁移的能力：升级需要重刷镜像并清空整张 SD 卡，卡上的录像和配置不保留。

2.0 面向 Luckfox Pico Pro Max。Pico Ultra 排在[它之后](#luckfox-pico-ultra)。

### 板子
- [x] 镜像中带一个只读的板级文件，声明这块板子有什么（取代型号检测）
- [ ] 模块按板级文件和用户配置决定是否启动
- [x] 板级文件和用户配置都用 JSON（取代 `config.yaml`）
- [x] 存储位置来自板级文件（取代写死的挂载点）
- [x] 录制前检查存储已挂载，不会写进 flash

### 进程
- [x] 进程退出后自动重新启动
- [x] 看门狗，只由录制进程来喂

### 升级
- [x] 带 `misc`、`recovery` 和能放下升级包的 `userdata` 的分区表，在 2.0 发布前就位：以后再改就要再重刷一次。见 [BUILD_cn.md](BUILD_cn.md#分区) 的*分区*一节
- [x] 通过 recovery 升级：上传的升级包在重启后刷入，中途掉电的刷写会从头再来。见 [BUILD_cn.md](BUILD_cn.md#升级) 的*升级*一节
- [ ] 升级接口提供给用户之前先有登录：现在任何能访问 agent 的人都能给板子刷固件
- [x] `/api/status` 和状态页面上的版本号：看版本号就知道升级有没有成功
- [ ] 升级页面

### 前端
- [ ] 重新设计前端，使用 Vue + Vite
- [ ] 功能与现有页面持平
- [ ] 日志页面，同时显示安全模式和失败启动计数
- [x] agent 的路径已按 [API_cn.md](API_cn.md) 的命名空间划分。它的字段规则还有三处没做到：
- [ ] `/api/status` 去掉格式化好的旧字段（`cpuTemp`、`systemUptime`、`lastRecord` 等）：它们随读取它们的手写页面一起移除
- [ ] 录像接口返回的时间用 RFC 3339：现在的 `startTime` 只是当天的时刻
- [ ] `/api/recordings/calendar` 的 `state` 说明含义，而不是一个数字
- [x] 实时画面改为 H264 经 WebRTC 传输（取代 MJPEG）：agent 在 `POST /api/stream` 应答 offer
- [x] 用 `<video>` 播放它的实时画面，`/v2/` 下的 Vue 页面和手写页面都已改用它

### 录制
- [ ] 事件改为区间，取代数据库里现在的标记。设计见 [events_cn.md](events_cn.md)
- [ ] 优化运动/静止切换逻辑，使运动更连贯。它和事件在哪里结束是同一次判断
- [ ] 设置和秘密放在板子上，不放在卡上；恢复出厂会擦除它们，通过长按按钮触发

### 开发
- [x] PC 模拟器，前端开发不需要板子
- [x] 全栈开发环境（devcontainer 中加入 Node.js）
- [x] 模拟器不再依赖板子上的固定目录

## 2.0 之后

### Luckfox Pico Ultra

目标日期：待定。

2026-11-27 从 2.0 中移出。Pro Max 可以通过 USB 访问，电脑和手机都行，看录像的需要已经满足；而 Ultra 有、Pro Max 没有的音频，目前用不上。

- 板级配置，包括挂载它外部存储的规则
- 升级：eMMC，以及它自己的板级文件
- CI 并行发布两个板子
- 音频。录像数据库的设计给它留了位置，但一点都没有实现：见 [events_cn.md](events_cn.md#不在这份设计里) 的*不在这份设计里*一节

### 功能
- 外设
  - 四寸屏幕，作为独立进程，支持运动唤醒
  - OLED
  - 温湿度
  - 舵机
  - 麦克风
  - 喇叭（提示/问候音，报警音）
- 网络
  - 解决 IP 地址固定问题，简化配置
  - 通过 WiFi 客户端（或 AP）或有线网络访问
  - 通过 USB 网络访问
- 基础 AI 功能（用 NPU 跑 YOLO 等）
  - 人体检测
- 环境光照补偿或替代方案，避免误触发运动记录
- 认证
- OTA

### 其他
- 进一步精简镜像：板子上没有的硬件所对应的内核模块
